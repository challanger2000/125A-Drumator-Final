# Drumator V1.0.1 — GUI/UX redesign specification (draft 01)

Status: **DESIGN IN PROGRESS — NOT APPROVED FOR VSTGUI IMPLEMENTATION**.
Date: 2026-10-27. Branch: `develop/v1.0.1-gui-redesign`.
Starting baseline: Final repository commit `e84df4ea8c317e12bf792a0a2396c810ed2d6f02`.
V1.0.0 main, binary, and packaging are not to be modified or reclassified as released.

## Product concept

**FL Studio-style multi-row step sequencer within the housing of a high-quality hardware drum machine.**
The 32 step controls (single continuous horizontal line per instrument), their dark-blue wells, orange on-state, and collapsible per-row velocity lane are the distinguishing strengths and **must be preserved**.
Roland TR-808/909, D16 Drumazon 2, Sugar Bytes DrumComputer, Arturia Spark 2 and XLN XO are UX/industrial design references, not material or code to copy.

## Owner decisions already made

- Entire plugin must be operable through ordinary mouse interactions. Shift/Ctrl/Alt gestures may remain optional, never sole access.
- Always-visible: actions used frequently during sequencing. Secondary operations may reside in obvious, mouse-accessible contextual menus or expanding sections.
- Hardware-like, disciplined layout: repeated controls form a fixed sizing system. Text length must not determine per-instance button width. Consistent alignments/gutters and limited button families.
- Labels may be abbreviated when context makes them clear; document abbreviations in the manual. `PTNR` preferred over `PATTERN MENU`.
- Minimum necessary width per component, with adequate hit targets and legibility at 100/120/130/150% zoom. Do not fill all newly freed space.
- Keep header controls on one horizontal band rather than inventing additional stacked control rows.
- Consider a matte cream-white instrument faceplate and black hardware buttons, but do not recolor the dark pattern background/steps. Color/material choice remains **PROPOSED**, not approved final.
- Preserve the existing sound engine, automation/state IDs, source/asset loading, host and song functionality.

## Proposed interaction map (to be approved before coding)

1. Sample selection field comprises filename + integrated previous/next arrows; direct mouse click to load remains.
2. Adjacent small Preview (triangle), EDIT, and visible `...` sample-menu entry.
3. M and S in a fixed shared button family. Group VOL, PAN, PITCH symmetrically; avoid variable-width adjacent controls.
4. Keep step well **exactly in one 32-step row** and the current VEL toggle/lane.
5. Consolidate ROW commands via contextual ROW menu close to the row identity; place routing/choke in a discoverable secondary control section if owner agrees.
6. Keep A–H and compact `PTNR` menu next to each other; one compact 1/2 BAR chooser; song and global controls in same horizontal head band.
7. Never hide necessary sample rename/remove, knob reset, or pattern length behind mandatory keyboard modifiers.

## Audited SONG editor — actual controls and mouse access

Source: `src/vst3/DrumatorView.cpp` around lines 1340–1445 and 2111–2169.

- SONG view replaces instrument-grid content while preserving the global header.
- SONG CHAIN shows existing entries only in paged tiles; each tile shows index, A–H or REST, and length. Clicking selects an existing entry. Empty tiles intentionally do not add entries.
- SON​​G START uses decrement, BAR number readout, increment (range 1–9999), plus RESET to 1. All have direct mouse interaction.
- PREVIOUS/NEXT paginate the chain; ADD ENTRY appends up to 64; REMOVE LAST removes down to one. Controls must preserve selected slot and paging rules.
- Selected entry can choose A–H or REST and independently choose 1/2 BAR (8 steps), 1 BAR (16), 2 BARS (32), all direct mouse controls.
- Initial UX recommendation: retain direct entry tiles and A–H/REST; standardize tile typography and pattern letter column. Replace text-heavy navigation with standard arrow button family and a visible page-position readout. Compact `ADD` / `DEL` buttons with clear SONG section context; keep deletion unambiguous and gated at 1. Group SONG START numeric + / − and RESET in one compact assembly, not scattered buttons. Do not change underlying chain behavior.
- 64-entry limit, pattern/rest selection and recall are functional contracts. The proposed visual change is not authority to modify serialization or sequence timing.

## Audited SAMPLE editor — actual controls and mouse access

Source: `src/vst3/DrumatorView.cpp` around lines 1513–1660, 1811–1874 and 1886–1965.

- Modal editor occupies current overlay rectangle (230,100)–(1050,605).
- Stereo/mono peak waveform with START and END markers, editable by direct mouse drag; fade-in/out handles draggable. Preview waveform changes are visualization, not permission to change source PCM.
- Horizontal waveform scrollbar can be dragged; ZOOM +, ZOOM − and FIT have dedicated clickable controls.
- GAIN slider can be dragged directly; its actual percentage is shown; Ctrl-click/double-click reset is currently additional convenience.
- Numeric readouts show START, END, FADE IN, FADE OUT in milliseconds and GAIN percentage; those labels/readouts are currently not numeric text-entry controls.
- PREVIEW and STOP play/cancel pending audition. RESET returns sample-edit values to defaults. CANCEL abandons, APPLY commits (after stopping preview successfully); failed STOP must not incorrectly commit.
- UX recommendation: preserve dominant waveform, visible draggable START/END/fade handles, scrollbar and GAIN slider; standardize compact toolbar button sizes. Separate **transport** (preview/stop), **viewport** (+/−/fit), **edit** (reset), **transaction** (cancel/apply) visually. Clearly distinguish destructive/global RESET from ordinary zoom reset. Show labels/values without inventing nonexistent editing by mouse.
- Mouse-only usability warning: existing empty-waveform click sets START by default and requires Shift to target END when click is not near its marker. This is a real mouse-only discoverability defect; proposed remedy is explicit START/END selection mode or two small selectable marker controls, followed by ordinary mouse click/drag. Preserve existing near-marker direct dragging and support overlapping markers at narrow zoom.
- Restore GAIN to unity without modifier via visible 100% tick or an explicit mouse-accessible `1×` reset, as a proposal; retain standard Ctrl-click actual-default reset for compatibility.
- Test failures: cancel/apply when stop fails, source replacement during editor open, revision changes, zoom/scroll bounds and redraw, host resize/zoom and project recall.

## UX review conclusion after all primary sections

- **Primary step rows:** keep dark step wells and their 32 same-line hardware keys unchanged, including existing collapsible velocity editor.
- **Song editor:** one dedicated, logically grouped mode with compact standardized navigation and directly clickable A–H/REST/length options.
- **Sample editor:** waveform-driven direct manipulation takes priority over additional menus; reorganize toolbar into functional groups rather than shrinking everything indiscriminately.
- **Header:** remains one horizontal control band; 1/2 BAR, A–H and `PTNR` adjacent, then SONG and global controls. Retain meters and zoom.
- **Bottom footer:** presently ADD ROW, REMOVE ROW, instrument count/page arrows and status line. Proposal: compact `+` / `−` with explicit instrument context, arrows beside range/page indicator; avoid confusing these with sample selection arrows.
- **Next design deliverable:** a true 1280px dimensioned static layout for header + four rows + footer, and separate SONG/SAMPLE editor views; no release claim or changes to source interaction rectangles until reviewed.
